WHAT THIS IS

A FRED-style site for Chinese official statistics: 15,078 stored series,
1.32 million observations, live at
https://econstats-china-production.up.railway.app

Stack: Bun + React 19 + Recharts + SQLite. Everything server-side reads a
store first and falls back to the source. Repo github.com/joshfwaldman1/datatool,
working copy /Users/josh/Downloads/econstats-agent-extract/econstats-agent-main.

Read AGENTS.md at the repo root first. It is the real project document and it
is current: sources and how each is reached, the store's rules, search and
glossing, transforms, deployment. This file only covers what AGENTS.md cannot,
namely where the work stands and what to do next.


HOW THE WORK IS ORGANISED

china-explorer/LOOP.md is a standing instruction: one small, verified
improvement per round, forever, until the owner stops it. Read it before
starting, and follow it rather than inventing a process.

china-explorer/IMPROVEMENT_LOG.md holds the queue and a dated entry for every
round. 208 rounds are logged. The log is the memory of what was checked and
found sound, so read the last twenty entries before picking work, and append
one entry per round.

The short version of the loop: pull, pick the top queue item or audit one
surface, reproduce the problem on the live site before changing code, make the
change, gate on both checks below, commit, push, deploy, verify live, log it.


COMMANDS

  bun run china              start the dev server (port 5173)
  bun run china:start        production mode, serves the built client
  bun run china:ingest       refresh every curated series; pass keys to narrow
  bun test                   139 tests, 6 files. Must pass.
  bunx tsc --noEmit -p tsconfig.json | grep china-explorer   must print nothing

The typecheck gate has a trap with history: a tsconfig error makes tsc exit
before checking any file, so a clean grep can be vacuous. Read the whole tsc
output, not just the grep.

There are 34 pre-existing type errors in src/, relay/ and mcp/. They are not
from this project; leave them.


DEPLOYING

A push does NOT deploy. Railway is not linked to GitHub. Deploy with

  railway up --detach

from the repo root, then verify on the live URL. The Railway CLI is already
linked to project econstats-china in the EconStats workspace. `railway login`
only works from Terminal.app, never a non-interactive shell.

At each container switch the edge answers 502 for a few seconds; a check that
fails right after a deploy should be retried before it is believed.

The store lives on a Railway volume at /data, not in git. Never run
`bun run china:seed` (it would copy the whole store into the repo; the seed is
headline-only by design), never commit china.db or catalog.db.


WHAT CHANGED IN THE LAST SESSION (rounds 170-208, 11 September)

Two of these were real errors in the numbers, both found by checking the site
against figures the National Bureau of Statistics publishes itself. If you
change anything near dates or periods, re-run those checks.

1. Year-over-year was wrong on every gapped monthly series. The transform
   counted twelve array positions back, and the bureau publishes no January
   (January and February are released together as the February point), so July
   was compared with the previous June. Crude steel output read +111% for
   February 2026 where the bureau published -3.6%. Fixed: the comparison
   period is matched by its label (shiftPeriod in server/nbs-catalog.ts). A
   period whose comparison period is missing now yields no point.

2. The February fill was mixing one-month and two-month readings. It copied
   the year-to-date sibling's January-February total into any series missing a
   February, but some series publish a single-month February in most years.
   Passenger traffic held 139,505 for February 2026 beside a filled 276,370
   for February 2025, giving -49.5% where the bureau published +0.9%. Fixed:
   only a series with no February anywhere is filled, and frequency
   conversion's tolerance for one missing reading follows the same flag
   (Track.combinedFebruary).

Also shipped: level series now carry a note that the bureau computes growth on
a comparable enterprise scope while publishing levels on the current scope, so
arithmetic on levels will differ (crude steel by 0.2 points, cement 2.5,
integrated circuits 12); a fetch that reads exactly 0 everywhere over stored
values is rejected rather than archived as a revision, after a bad Eastmoney
response stored M1 and M2 as 0.0; leading placeholder zeros are dropped from
level, index and long-run rate series on read; CSV downloads name their
region; health reads MAX(rowid) instead of counting 1.3 million rows;
category cards read English first; search matches plurals and drops the scope
qualifiers the bureau keeps in annotations.


STANDING FACTS THAT ARE EASY TO GET WRONG

- Arithmetic year-over-year on a bureau level series is never the published
  growth rate. The enterprise sample changes yearly; the bureau holds the
  scope comparable, the levels do not. Do not "fix" a gap between them.
- observations is append-only. A row is written only when the value differs
  from the last stored one, so revisions accumulate. Rows are never deleted by
  code, and the health count relies on that. Two false vintages from the
  Eastmoney glitch stand on purpose.
- Only raw values are stored. Transforms are applied on the way out.
- Some things look like bugs and are not: Caixin PMI ends September 2025
  (sponsorship moved), the Real Estate Climate Index stops December 2025 in
  the mirror used here, some catalog entries return no data because the bureau
  still lists discontinued indicators, /health is deliberately trivial.
  LOOP.md keeps this list; add to it rather than re-investigating.
- The three AkShare-backed series are not refreshed on this deployment, which
  does not run AKTools. That is stated on their pages, not hidden.
